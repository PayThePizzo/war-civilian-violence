## Pipeline from raw information to the visualizations

The actor view reads one derived file, `actor_profiles.csv`. All analytical work happens upstream in the Python pipeline, while the browser only filters, scales and lays out.

The whole pipeline runs with `python scripts/build_all.py`.

**What is inside the raw dataset.**

- Each UCDP GED event names its two sides (`side_a`, `side_b` with ids) and the violence type. A combat event involves two armed actors; a one-sided event has one perpetrator (`side_a`), and civilians are never treated as an actor.

**What is inside `actor_profiles.csv`.**

- One row per canonical actor (22 actors, 11 flagged `eligible_for_web3`). 

The parallel-coordinates plot uses six fixed axes:

| Column | Axis |
|---|---|
| `combat_event_count` | combat involvement (symlog scale) |
| `actor_deaths_suffered` | losses suffered (symlog scale) |
| `one_sided_event_count` | one-sided events (symlog scale) |
| `one_sided_civilian_fatalities` | civilian toll (symlog scale) |
| `one_sided_event_share` | share of the actor's events that were one-sided (linear, 0 to 1) |
| `active_h3_cell_count` | geographic spread (symlog scale) |

The detail panel also shows:

- `total_event_count`, first/last event date, active weeks and per-active-week rates;
- `combatant_fatalities_in_involved_events` counts deaths in combat events the actor took part in and is not the actor's own losses;
- `actor_deaths_suffered` is kept separately for that.

### Steps

1. **Download the raw GED** (v26.1) into `data/raw/GEDEvent_v26_1.csv`, kept unmodified.
2. **`01_clean_events.py`** validates required columns, unique event ids, parseable dates and `date_start <= date_end`, restricts the data to Sudan and 2023-04-15 to 2025-12-31, derives `combatant_fatalities`, `civilian_fatalities` and `one_sided_civilian_fatalities`, and flags (does not drop) events with invalid coordinates. Output: `data/processed/events_clean.parquet`, one row per event.
3. **`02_build_actor_events.py`** expands each event into actor × event rows (a combat event becomes two rows, one per side; a one-sided event becomes one row, the perpetrator). Output: `data/processed/actor_events.parquet` and `actor_lookup.csv`.
4. **`05_build_actor_profiles.py`** groups the actor-event rows by `actor_id`, attaches the canonical name from `actor_lookup.csv`, and computes activity, fatality, one-sided and geographic-spread metrics (spread uses H3 cells at the same resolution as the map, from spatially eligible events only). It sets `eligible_for_web3` from `actors.min_events` (5) but removes no one. Output: `data/derived/actor_profiles.csv`.
5. **`07_validate_outputs.py`** runs 146 checks (all pass) over every processed and derived file. `build_all.py` runs all stages in order, stops at the first failure, and also writes `metadata.json` (country, analysis period, week convention, H3 resolution, window size).
6. **`npm run sync-data`** (in `web/`, run automatically by `npm run dev` and `npm run build`) copies the five derived files unchanged into `web/.generated/data/`.
7. **At startup** `src/data/loaders.ts` fetches and parses the files through `parsers.ts`, which fails loudly on schema drift and keeps `null` (not observed) distinct from `0`. Views read only through `src/data/selectors.ts`.
8. **`ActorParallelCoordinates.ts`** takes `getActorProfiles(data, showMinorActors)`, which keeps only `eligible_for_web3` rows unless the 'Show minor actors' box is ticked (the threshold is never re-derived in the browser). `actorMath.ts` builds one scale per axis (symlog for the skewed counts, linear for the share) and the polyline points; each actor is one line.
9. **Interaction:** hovering highlights an actor's line and fills the detail panel (local state); clicking a line writes `selectedActorId` to the global store, which switches the timeline to that actor's series, restricts the map to its cells and shows its episodes in the before/after view.

### Sources and tools

**Data sources**

| Source | Role |
|---|---|
| UCDP Georeferenced Event Dataset (GED) v26.1, `data/raw/GEDEvent_v26_1.csv` (codebook: `data/raw/ged261.pdf`) | events, sides, fatalities, coordinates |
| `config/config.yaml` | `actors.min_events`, `spatial.h3_resolution` |

**Pipeline tools (Python 3.12, Poetry)**

| Tool | Use |
|---|---|
| pandas, numpy | cleaning, joins, aggregation |
| pyarrow | Parquet files for `events_clean` and `actor_events` |
| h3 (`h3-py`) | H3 cells for the geographic-spread metric |
| pyyaml, pydantic | reading and validating `config.yaml` (`config/config_parser.py`) |
| flake8, black | linting and formatting |

**Rendering tools (`web/`, Node, TypeScript)**

| Tool | Use |
|---|---|
| Vite | dev server and production build |
| TypeScript | typed CSV parsing and view code |
| D3 (`d3`) | `scaleSymlog`/`scaleLinear`, line generation, axes |
| Node test runner (`node --test`) | unit tests for the pure `*Math.ts` helpers (`npm test`) |
| Source Serif 4 and Public Sans | self-hosted variable fonts for headings and controls/axes |
