# X Post 1

**Title**: Before the killings, no clear warning in the fighting

**Description**: Do major attacks on civilians follow a visible escalation in battlefield activity?

Looking at the eight weeks before and after El Fasher massacre, the pattern is mixed: combat activity changes only modestly, with no consistent rise before the peak.

Data: UCDP Event Dataset.

![X Post 1](https://github.com/PayThePizzo/war-civilian-violence/blob/main/docs/phase_3/images/X1%20-%20screenshot.png?raw=TRUE)

---

## Context

This post addresses the temporal question at the core of the final stage of the project:

> **Do major episodes of one-sided violence against civilians tend to be preceded by a visible escalation in battlefield activity?**

The objective is not to establish that combat activity causes subsequent civilian targeting. Instead, the visualization examines whether a recognizable **temporal association** appears around major episodes of one-sided civilian violence.

Ordinary calendar time makes this comparison difficult because the episodes occur on different dates and involve different actors. The project therefore reorganizes each episode around a common reference point:

\[
T0 = \text{week of a selected peak in one-sided civilian fatalities}
\]

and compares the eight weeks before and after that peak:

\[
T-8,\ldots,T-1 \mid T0 \mid T+1,\ldots,T+8
\]

This event-centred transformation is defined upstream in the analytical pipeline rather than manually in the visualization. :contentReference[oaicite:0]{index=0}

For the X post, the more complex interactive Web Visualization 4 was condensed into a **single explanatory graphic**. The matrix of individual episodes was removed, while the summary pattern, the T0 reference point, the civilian-fatality markers and one key quantitative finding were retained.

The communication goal is therefore narrower than in the web version:

> **Does the aggregate pattern provide an obvious battlefield warning before major civilian-violence peaks?**

## Representation: Event-centred Summary Timeline

![X Post 1](https://github.com/PayThePizzo/war-civilian-violence/blob/main/docs/phase_3/images/X1.png?raw=TRUE)

The visualization is a **relative-time summary chart** centred on T0.

Its horizontal axis does not represent ordinary calendar dates. Instead, it shows relative weeks:

- **8 weeks before** the selected peak;
- **T0**, the reference week;
- **8 weeks after** the peak.

This allows episodes occurring at different moments in the conflict to be placed on the same analytical timeline.

### Upper panel — Combat activity

The upper chart shows the distribution of **combat events per week** across the displayed episodes.

Two elements are used:

- the **orange line** represents the median number of combat events at each relative week;
- the **shaded band** represents the interquartile range.

This is the same summary logic used by the interactive Web Visualization 4: the line represents the median of the selected background metric and the surrounding band represents its first-to-third-quartile range. :contentReference[oaicite:1]{index=1}

A vertical dashed line identifies **T0**.

The use of median and interquartile range is useful because conflict episodes can differ substantially in magnitude. Instead of allowing a few extreme observations to dominate the representation, the chart communicates both:

> **the typical level of combat activity**

and

> **how variable that activity is across episodes.**

Visually, the median line changes relatively modestly before T0. There is no clear monotonic escalation as the peak approaches. The broad interquartile band also indicates substantial variation between episodes.

This is the basis for the headline:

> **Before the killings, no clear warning in the fighting**

The claim is intentionally about the **absence of a clear common pattern**, not about the absence of combat activity.

### Lower panel — One-sided civilian fatalities

Below the combat summary is a second temporal strip showing **one-sided civilian fatalities**.

Each dot corresponds to a relative week, and dot area represents the median number of one-sided civilian fatalities.

The dominant red circle at T0 visually identifies the peak around which all episodes have been aligned.

This provides an important visual contrast:

- combat activity is represented by the line and uncertainty band;
- the civilian-violence peak is represented by the red dot series.

The reader can therefore compare the development of battlefield activity with the moment around which the civilian-violence episodes are defined.

The underlying event-window data contains both the surrounding military-context variables and `one_sided_civilian_fatalities` for each relative week. :contentReference[oaicite:2]{index=2}

### El Fasher as the reference episode

The graphic labels T0 as:

> **T0 (EL FASHER MASSACRE)**

and includes satellite imagery of the El Fasher massacre site.

El Fasher serves as the narrative reference point for the post, making the otherwise abstract T0 concept concrete.

The satellite image is **contextual rather than analytical**: it is not used to derive the UCDP metrics or the plotted statistical summary. Its role is to connect the event-centred data representation with the physical context of the selected episode.

### Key finding

The callout at the bottom provides a more explicit quantitative test of the visual impression:

> **14 of 26 episodes with a complete 8-week window had higher combat activity in the four weeks before El Fasher's Massacre than in the previous four.**

The important aspect of this result is that the episodes are divided relatively evenly.

If a strong and consistent pre-peak escalation pattern existed, substantially more episodes would be expected to show increasing combat activity immediately before T0.

Instead, the finding is compatible with the visual message of the line chart:

> **the pattern across episodes is mixed rather than consistently escalating.**

Only episodes with a complete eight-week pre-peak observation window are used for this comparison, avoiding the treatment of unavailable weeks as if they represented zero activity.

The underlying pipeline explicitly distinguishes genuinely observed zero-activity weeks from weeks outside the observation period. :contentReference[oaicite:3]{index=3}

### Adaptation for X

Unlike Web Visualization 4, this representation is deliberately static.

The interactive version allows users to:

- change the background metric;
- inspect individual episodes;
- filter by actor;
- hover individual weeks;
- compare the event matrix;
- connect an episode to the Timeline, Map and Actor views.

For X, these options are removed. Instead, the graphic fixes **Combat events** as the background metric and emphasizes one clear analytical question.

This makes the post easier to interpret while scrolling, at the cost of losing the exploratory capabilities of the web version.

## Pros and Cons

| **Pro** | **Con** |
|---------|---------|
| Aligning episodes around **T0** makes events from different actors and calendar dates directly comparable. | Relative time removes much of the ordinary historical chronology, so the reader cannot see when most episodes actually occurred. |
| The median line and IQR band communicate both the **typical pattern and its variability**, rather than highlighting only one episode. | Aggregation can hide important episode-specific behavior: some individual episodes may show strong escalation even when the overall median does not. |
| Separating combat activity from civilian-fatality dots makes the distinction between **battlefield context and civilian violence** visually explicit. | The X version fixes combat events as the background metric and cannot expose alternative measures such as combatant fatalities or actor deaths suffered. |
| The key-finding callout supplements the visual pattern with a concrete comparison across the complete episode windows. | A before/after observational pattern cannot determine whether changes in combat activity caused civilian targeting. |

## Knowledge: What can we learn from it?

The visualization is designed to investigate whether major episodes of civilian targeting are preceded by a **common, visible escalation in armed conflict**.

Without this representation, the relevant information exists as rows in `event_windows.csv`: each episode contains separate observations for T-8 through T+8, together with combat events, combatant fatalities, actor losses and civilian fatalities. :contentReference[oaicite:4]{index=4}

A table can provide exact numbers, but it makes the overall temporal structure difficult to perceive.

In tabular form, it would be difficult to identify quickly:

- whether combat activity rises systematically as T0 approaches;
- whether the typical level at T-1 is substantially different from T-8;
- how variable the episodes are around the median;
- whether the civilian-fatality peak coincides with an exceptional combat peak;
- whether the apparent pattern is broadly shared or driven by a few individual episodes.

The event-centred representation solves the first problem through **alignment**.

Instead of comparing unrelated calendar dates, every episode shares the same reference structure:

\[
T-8 \rightarrow T-1 \rightarrow T0 \rightarrow T+8
\]

The summary then allows the reader to look for systematic changes around the common reference point.

What emerges from this representation is not a clear pre-T0 escalation.

The median number of combat events fluctuates, but it does not display a sustained upward trajectory toward T0. The interquartile band remains relatively broad, showing substantial heterogeneity among the individual episodes.

The additional finding reinforces this interpretation: among the 26 episodes with complete eight-week windows, 14 showed higher combat activity during the four weeks immediately preceding the El Fasher reference peak than during the previous four weeks.

This is only slightly more than half of the eligible episodes.

The representation therefore suggests that:

> **A simple pattern of steadily intensifying combat before major one-sided civilian-violence episodes is not consistently visible in these data.**

That conclusion is more informative than either extreme interpretation.

The visualization does **not** show that battlefield conditions are unrelated to civilian targeting. Some individual episodes may still be associated with substantial escalation, and other military-context metrics may behave differently.

It shows instead that **combat-event frequency alone does not provide a clear, uniform warning pattern across the episodes examined**.

This is also why the shaded IQR is important. The width of the band indicates that the conflict episodes are heterogeneous. A single average trajectory would conceal this variation.

The representation therefore gains something that is difficult to obtain from either individual case studies or a large table:

> **a compact view of the common temporal pattern together with the variation around it.**

Finally, the interpretation must remain descriptive. The event-window dataset was explicitly constructed to support analysis of temporal patterns around peaks, not to estimate causal effects. The pipeline documentation states that these patterns cannot demonstrate that preceding military activity caused subsequent violence against civilians. :contentReference[oaicite:5]{index=5}

The X post consequently communicates a restrained result:

> **There is no obvious, consistent surge in combat activity before the major civilian-violence peaks represented here.**

Rather than proving a causal mechanism, the visualization shows that the relationship between battlefield escalation and civilian targeting is **more heterogeneous than a simple "fighting rises, then civilians are attacked" narrative would imply**.

## Pipeline from raw information to the visualizations

The post reads one derived file, `event_windows.csv`, plus `metadata.json` for the window size. All analytical work happens upstream in the Python pipeline, while the `social/` only filters, scales and lays out.

The whole pipeline runs with `python scripts/build_all.py`.

**What is inside the raw dataset.**

- Each UCDP GED event has a date range, a violence type, its sides and fatality estimates, from which the pipeline derives combat activity and `one_sided_civilian_fatalities`.

**What is inside `event_windows.csv`.**

- One row per episode × relative week (459 rows, 27 episodes, T-8 to T+8).

This post uses:

| Column | Used for |
|---|---|
| `episode_id`, `t0_date`, `peak_rank`, `peak_metric_value` | grouping rows into episodes |
| `relative_week` | x axis, T-8 to T+8 |
| `is_observed_week` | excludes weeks outside the analysis period from every statistic |
| `combat_event_count` | median line and IQR band, and the near/far count |
| `one_sided_civilian_fatalities` | dot strip: dot area proportional to the weekly median |

### Steps

1. **Download the raw GED** (v26.1) into `data/raw/GEDEvent_v26_1.csv`, kept unmodified.
2. **`01_clean_events.py`** validates required columns, unique event ids, parseable dates and `date_start <= date_end`, restricts the data to Sudan and 2023-04-15 to 2025-12-31, derives `combatant_fatalities`, `civilian_fatalities` and `one_sided_civilian_fatalities`, and flags (does not drop) events with invalid coordinates. Output: `data/processed/events_clean.parquet`, one row per event.
3. **`02_build_actor_events.py`** expands each event into actor × event rows (a combat event becomes two rows, one per side; a one-sided event becomes one row, the perpetrator). Output: `data/processed/actor_events.parquet` and `actor_lookup.csv`.
4. **`03_build_weekly_metrics.py`** builds the zero-filled weekly series per actor and **`05_build_actor_profiles.py`** builds the actor profiles; both are inputs of the next step.
5. **`06_build_event_windows.py`** finds, per actor, local maxima of `one_sided_civilian_fatalities`, ranks them, keeps peaks at least 6 weeks apart (top 10 per actor) and writes 8 weeks either side of each peak week T0. Weeks outside the analysis period are missing with `is_observed_week = False`, not zero. Output: `data/derived/event_windows.csv`.
6. **`07_validate_outputs.py`** runs 146 checks (all pass) over every processed and derived file. `build_all.py` runs all stages in order, stops at the first failure, and also writes `metadata.json` (country, analysis period, week convention, H3 resolution, window size).
7. **`npm run sync-data`** (in `social/`) copies the derived CSVs and `metadata.json` unchanged into `social/.generated/data/`.
8. **`x/post-01-before-after/main.ts`** loads the rows through `shared/data.ts`, groups them by `episode_id`, and for each relative week computes the median and the first and third quartiles across episodes using only observed, non-null values.

   It draws the median combat-event line with an IQR band and a T0 reference line, a dot strip of the median one-sided civilian fatalities per week, and one descriptive statistic: among episodes with a fully observed window on both sides, how many had more combat events in the four weeks before T0 than in the four weeks before that. It is a plain count, with no test and no causal claim.
9. **`npm run export:x`** builds the pages with Vite, renders each at 1600 × 900 px with Playwright and writes `social/output/x-01-before-after.png`.

This is not a screenshot of the web matrix: the per-episode rows, metric selector and details panel are not carried over, only the pipeline-defined episodes and the semantic colors.
