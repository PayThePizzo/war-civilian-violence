# Responsive Web Visualization 2

## Context: Where

The second web visualization addresses the spatial question of the project:

> **Where does violence concentrate geographically, and does violence against civilians follow the same spatial pattern as direct combat?**

After the timeline establishes **when** the composition of the conflict changes, the map adds the geographic dimension.

The objective is to determine whether state-based and non-state combat and one-sided violence occur in the same areas, whether distinct hotspots emerge, and whether these patterns move across Sudan over time.

---

## Representation: Map ("02 / WHERE?")

Plotting every individual event as a point would create substantial overlap in areas with many observations and would make comparisons between regions difficult. For this reason  events are aggregated into **H3 hexagonal cells**. 

![Web 2 - 2D](https://github.com/PayThePizzo/war-civilian-violence/blob/main/docs/phase_3/images/Web2%20-%202D.png?raw=TRUE)

Each cell provides a consistent geographic unit in which event frequency, fatalities and violence composition can be summarized. Only cells containing at least one spatially eligible event are included.

### What it represents

Where violence concentrates geographically across Sudan, and how combat versus one-sided
intensity differs by location.

### What it shows

![Web 2 - Play](https://github.com/PayThePizzo/war-civilian-violence/blob/main/docs/phase_3/images/Web2%20-%20Play.png?raw=TRUE)

An H3-hexagon choropleth over an OpenStreetMap base layer. Two modes:

- **Overview** (default) - hexagons aggregated across the full analysis period.
- **Week** - hexagons for a single week, entered automatically when a week is clicked in Timeline
  (or advanced manually with a ◀ / Play / ▶ stepper).

Hexagon colour ranges from combat to one-sided violence (orange -> red) using the selected share
metric. The selected intensity metric—events, best-estimate fatalities, or one-sided civilian
fatalities—controls **opacity** in 2D and **height** in 3D. Labels and the legend identify the
current actor, time scope, visual encodings and number of active cells.

![Web 2 - 3D](https://github.com/PayThePizzo/war-civilian-violence/blob/main/docs/phase_3/images/Web2%20-%203D.png?raw=TRUE)

The OpenStreetMap basemap provides geographic context, while regular **hexagonal spatial units**
represent the analytical data without relying on irregular administrative regions.

The visualization uses two channels simultaneously:

- **Colour** represents the composition of violence. The scale moves from the combat side of the spectrum toward the one-sided side according to the selected share metric.
- **Intensity** represents magnitude. Depending on the selected option, this can refer to the number of events, best-estimate fatalities, or one-sided civilian fatalities.

Separating **composition** from **magnitude** reveals when similarly active cells have different
violence profiles, or when a strongly one-sided cell contains relatively little activity.

In the 2D overview, **one-sided civilian fatalities** control intensity and their share controls
colour. The 274 active cells show both where these fatalities occurred and how dominant they were.

The 3D example uses `one_sided_event_share` for colour and total events for height. It emphasizes
spatial concentration, but serves mainly as an exploratory alternative to the more precise 2D view.

The third screenshot shows **Week mode** for **SFA · Week of 20 Oct 2025**, with 12 active cells.
The hovered cell contains 38 events: 9 combat and 29 one-sided.

Clicking a week in Web Visualization 1 sets the shared `focusWeek` and opens the same week on the
map. The stepper and **Play** control then show how the spatial pattern changes over time.

The interactive options include:

- **Overview / Week:** switches between the complete-period spatial pattern and one specific week.
- **Previous / Play / Next:** steps through the observed weeks while in Week mode.
- **Actor selection:** the map follows the globally selected actor, allowing the same geographic analysis to be repeated for individual armed actors.
- **Intensity selector:** changes the magnitude variable represented by opacity or height.
- **Colour selector:** changes the share variable used to describe the composition of each cell.
- **2D / 3D:** switches between opacity-based and height-based representations of intensity.
- **Hover:** displays the complete metric breakdown for an individual H3 cell.

The compact visual encoding supports quick pattern recognition, while the tooltip provides exact
event, composition and fatality values for each cell.

## Pros and Cons

| **Pro** | **Con** |
|---------|---------|
| H3 aggregation makes geographic **hotspots, clusters and spatial shifts** much easier to perceive than individual event coordinates or tabular latitude/longitude values. | Aggregation into hexagons removes the exact location of individual events and can hide variation occurring inside the same cell. |
| Separating **colour for composition** from **opacity/height for magnitude** makes it possible to distinguish highly active areas from areas where one-sided violence is proportionally dominant. | Reading two visual channels simultaneously increases cognitive load, particularly when both colour and intensity vary strongly across the map. |
| Overview and Week modes allow the same representation to support both **long-term spatial structure** and **short-term temporal exploration**. | Weekly maps may contain relatively few observations, so extreme share values can sometimes be produced by a small number of events. |
| The 2D/3D switch, actor filtering, playback and timeline synchronization support several complementary ways of exploring the conflict. | 3D extrusion can introduce occlusion and perspective distortion, making precise comparison between cells harder than in the 2D view. |

## Knowledge: What can we learn from it?

The central question is whether different forms of violence follow the same geographic pattern or
develop distinct spatial concentrations.

The map allows us to investigate several related questions:

- Where are the main concentrations of recorded conflict activity?
- Do areas with many combat events also contain high levels of one-sided violence?
- Are there locations where violence against civilians becomes dominant even though overall activity is relatively limited?

Tables can rank or report individual cells, but make it difficult to see:

- whether high-value cells form **clusters** or are dispersed;
- whether civilian-targeting hotspots coincide with major combat zones;
- how far an actor's activity extends or moves over time;
- whether patterns persist from the full-period overview to individual weeks.

The map makes distance, clustering and geographic spread directly perceptible instead of requiring
them to be reconstructed from coordinates.

Using **colour and intensity** together distinguishes composition from magnitude. A strongly one-sided cell with little activity is therefore not treated as equivalent to a highly active combat-oriented cell.

**Week mode** restores the temporal detail hidden by full-period aggregation, showing whether a
hotspot is persistent, temporary, expanding, contracting or shifting geographically.

The **actor filter** reveals where a specific actor was active and which type of violence
characterized that activity, exposing distinct spatial profiles among armed actors.

Overall, the map answers **where the conflict changes form**. It locates the periods identified in
the timeline before the next visualization moves from **where** to **who**.

## Pipeline from raw information to the visualizations

The map reads one derived file, `h3_weekly_metrics.csv`, plus `metadata.json`. All analytical work happens upstream in the Python pipeline, while the browser only filters, scales and lays out.

The whole pipeline runs with `python scripts/build_all.py`.

**What is inside the raw dataset.**

- Each UCDP GED event carries `latitude`, `longitude` and a `where_coordinates` precision code alongside its violence type and fatality estimates. Events with missing or invalid coordinates are kept in the cleaned data but flagged `spatial_eligible = False`.

**What is inside `h3_weekly_metrics.csv`.**

- One row per actor × week × H3 cell, plus conflict-wide `__ALL__` rows. Only cells with at least one spatially eligible event get a row (the file is sparse, not a full grid).

The map plots these columns:

| Column | Used for |
|---|---|
| `h3_id`, `h3_center_lat`, `h3_center_lon` | cell identity and position (H3 resolution 5) |
| `event_count`, `best_fatalities`, `one_sided_civilian_fatalities` | intensity: opacity, or height in 3D |
| `one_sided_event_share`, `civilian_fatality_share`, `one_sided_civilian_fatality_share` | color, orange (combat) to red (one-sided) |
| `combat_event_count`, `one_sided_event_count`, `week_start` | tooltip breakdown and week mode |

Shares with a zero denominator are 0.

### Steps

1. **Download the raw GED** (v26.1) into `data/raw/GEDEvent_v26_1.csv`, kept unmodified.
2. **`01_clean_events.py`** validates required columns, unique event ids, parseable dates and `date_start <= date_end`, restricts the data to Sudan and 2023-04-15 to 2025-12-31, derives `combatant_fatalities`, `civilian_fatalities` and `one_sided_civilian_fatalities`, and flags (does not drop) events with invalid coordinates as `spatial_eligible = False`. Output: `data/processed/events_clean.parquet`, one row per event.
3. **`02_build_actor_events.py`** expands each event into actor × event rows (a combat event becomes two rows, one per side; a one-sided event becomes one row, the perpetrator). Output: `data/processed/actor_events.parquet` and `actor_lookup.csv`.
4. **`04_build_h3_metrics.py`** keeps only `spatial_eligible` events, converts each latitude/longitude to an H3 cell at the configured resolution (5), validates every cell id and resolution, and aggregates by week, cell and actor. Output: `data/derived/h3_weekly_metrics.csv` (3,057 rows; 274 distinct cells in the `__ALL__` series).
5. **`07_validate_outputs.py`** runs 146 checks (all pass) over every processed and derived file. `build_all.py` runs all stages in order, stops at the first failure, and also writes `metadata.json` (country, analysis period, week convention, H3 resolution, window size).
6. **`npm run sync-data`** (in `web/`, run automatically by `npm run dev` and `npm run build`) copies the five derived files unchanged into `web/.generated/data/`.
7. **At startup** `src/data/loaders.ts` fetches and parses the files through `parsers.ts`, which fails loudly on schema drift and keeps `null` (not observed) distinct from `0`. Views read only through `src/data/selectors.ts`.
8. **Overview mode** calls `aggregateH3Overview`, which sums counts per cell across all weeks and then recomputes the shares as ratios of the sums, never an average of weekly shares. **Week mode** calls `getH3ForActorAndWeek` and uses the rows directly.
9. **`H3Layer.ts`** turns the cells into a deck.gl `H3HexagonLayer`: fill color interpolates from combat to one-sided on the chosen share metric, and opacity (or height in 3D) scales with the chosen intensity metric. `ConflictMap.ts` owns the MapLibre map with an OpenStreetMap raster basemap and the deck.gl overlay.
10. **Interaction:** 
    1.  Hover shows a tooltip with the cell's activity, composition and fatalities;
    2.  An Overview/Week toggle and a stepper (◀ / Play / ▶) move through weeks;
    3.  Selectors change the color and intensity metrics and switch 2D/3D;
    4.  Clicking a week in the timeline enters week mode, and the selected actor restricts the cells;
    5.  The map never writes to the global store.
