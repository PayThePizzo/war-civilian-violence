# Data Files

This document describes the data files used and generated by the project **From Battlefield to Civilians: Patterns of One-Sided Violence in the Sudan Conflict**.

The data pipeline is organized into four logical levels:

```text
data/
├── raw/
├── processed/
├── derived/
└── validation/
```

The distinction is intentional:

- `raw/` contains the original source data and must not be modified by the pipeline.
- `processed/` contains cleaned or structurally transformed datasets that still preserve event-level information.
- `derived/` contains datasets produced specifically for analysis and visualization.
- `validation/` contains machine-readable reports about pipeline integrity.

Unless otherwise specified, all paths below are relative to the repository root.

---

## 1. `data/raw/GEDEvent_v26_1.csv`

### Purpose

Original **UCDP Georeferenced Event Dataset (GED) Global** file used as the source of the project.

This file is the immutable starting point of the pipeline.

### Format

CSV.

### Producer

External source: UCDP.

### Consumer

`01_clean_events.py`

### Unit of observation

One row corresponds to one UCDP event.

### Expected content

The pipeline expects, at minimum, fields describing:

- event identity;
- dates;
- violence type;
- conflict and dyad;
- side A and side B;
- location;
- geographic coordinates;
- fatality estimates.

Expected source fields include:

```text
id
date_start
date_end
date_prec

type_of_violence

conflict_new_id
conflict_name

dyad_new_id
dyad_name

side_a_new_id
side_a

side_b_new_id
side_b

country
adm_1
adm_2
where_coordinates

latitude
longitude

deaths_a
deaths_b
deaths_civilians
deaths_unknown

low
best
high
```

### Important rules

- The file must not be edited manually.
- The pipeline must never overwrite it.
- The original `id` field is expected to uniquely identify events.
- Dataset-specific validation happens in `01_clean_events.py`.

## 2. `data/processed/events_clean.parquet`

### Purpose

Canonical cleaned event-level dataset for the project.

It is the main source of truth for all conflict-wide calculations after the raw dataset.

### Format

Apache Parquet.

Parquet is used here because it:

- preserves data types more reliably than CSV;
- supports efficient loading;
- compresses large datasets;
- is appropriate for intermediate analytical data.

### Producer

`01_clean_events.py`

### Consumers

- `02_build_actor_events.py`
- `03_build_weekly_metrics.py`
- `04_build_h3_metrics.py`
- `07_validate_outputs.py`

### Unit of observation

One row = one retained UCDP event.

The transformation must preserve event-level uniqueness:

```text
event_id = primary key
```

### Main fields

#### Event identity

```text
event_id
```

Derived from the original UCDP `id`.

#### Dates

```text
date_start
date_end
date_prec
```

`date_start` is used as the canonical event date for this project.

#### Violence classification

```text
type_of_violence
violence_type_label
is_combat
is_one_sided
```

Definitions:

```text
type_of_violence = 1 → state-based
type_of_violence = 2 → non-state
type_of_violence = 3 → one-sided
```

For this project:

```text
is_combat = type_of_violence ∈ {1, 2}
is_one_sided = type_of_violence == 3
```

#### Conflict and dyad

```text
conflict_new_id
conflict_name
dyad_new_id
dyad_name
```

#### Actors

```text
side_a_new_id
side_a
side_b_new_id
side_b
```

#### Geography

```text
country
adm_1
adm_2
where_coordinates

latitude
longitude
spatial_eligible
```

`spatial_eligible` indicates whether the event has usable coordinates for H3 aggregation.

Events with invalid or missing coordinates remain in this dataset.

#### Fatalities

```text
deaths_a
deaths_b
deaths_civilians
deaths_unknown

combatant_fatalities
civilian_fatalities
one_sided_civilian_fatalities

low
best
high
```

Derived definitions:

```text
combatant_fatalities
    = deaths_a + deaths_b
    only for combat events

civilian_fatalities
    = deaths_civilians

one_sided_civilian_fatalities
    = deaths_civilians
    only when type_of_violence == 3
```

### Expected invariants

```text
event_id is non-null
event_id is unique

date_start <= date_end

type_of_violence ∈ {1, 2, 3}

fatality counts >= 0

low <= best <= high
when all three are available
```

Geographic coordinates are valid when:

```text
-90 <= latitude <= 90
-180 <= longitude <= 180
```

Invalid coordinates do not invalidate the event; they only imply:

```text
spatial_eligible = False
```

## 3. `data/processed/actor_events.parquet`

### Purpose

Actor-centric long-format representation of the event data.

The raw and cleaned event datasets store actors in separate `side_a` and `side_b` columns. This file transforms that structure into a form where the same actor can be followed consistently across direct combat and one-sided violence.

### Format

Apache Parquet.

### Producer

`02_build_actor_events.py`

### Consumers

- `03_build_weekly_metrics.py`
- `04_build_h3_metrics.py`
- `05_build_actor_profiles.py`
- `07_validate_outputs.py`

### Unit of observation

One row = one actor participating in one event.

Primary logical key:

```text
(event_id, actor_id)
```

### Expansion rules

For direct combat events:

```text
type_of_violence ∈ {1, 2}
```

both armed sides generate actor-event rows.

Example:

```text
event E1
side_a = Actor A
side_b = Actor B
```

becomes:

```text
E1 | Actor A | side_a
E1 | Actor B | side_b
```

For one-sided violence:

```text
type_of_violence == 3
```

only the armed actor is represented.

The civilian side must not be converted into a comparable armed actor.

### Main fields

```text
event_id

actor_id
actor_name
actor_role
is_one_sided_perpetrator

date_start

type_of_violence
is_combat
is_one_sided

combatant_fatalities
actor_deaths_suffered
civilian_fatalities
one_sided_civilian_fatalities

best
low
high

latitude
longitude
spatial_eligible

adm_1
adm_2
where_coordinates
```

### Actor identity

Whenever possible:

```text
actor_id = stable UCDP actor identifier
```

with a project prefix such as:

```text
ucdp:<id>
```

If the stable ID is unavailable, a normalized name-based fallback may be used:

```text
name:<normalized actor name>
```

Such cases should generate a warning.

### Important counting rule

This dataset must **not** be summed across all actors to reconstruct conflict-wide totals.

A direct combat event involving two actors appears twice by design.

Conflict-wide totals must always be calculated from:

```text
events_clean.parquet
```

### Expected invariants

```text
(event_id, actor_id) is unique

event_id exists in events_clean.parquet

actor_id is non-null

actor_name is non-empty where available
```

## 5. `data/derived/weekly_metrics.csv`

### Purpose

Primary dataset for **Web 1 — Conflict Timeline**.

It also provides the weekly actor time series used by the event-window analysis.

### Format

CSV.

### Producer

`03_build_weekly_metrics.py`

### Consumers

- Web 1 — temporal visualization
- `06_build_event_windows.py`
- `07_validate_outputs.py`

### Unit of observation

One row = one actor × one week.

The file also contains a synthetic conflict-wide actor:

```text
actor_id = "__ALL__"
actor_name = "All actors"
```

The `__ALL__` rows are calculated directly from unique events, not by summing actor-specific rows.

### Temporal definition

Weeks are Monday-to-Sunday.

`week_start` is the Monday associated with the event week.

The configured analysis period is expanded to a complete weekly grid so that weeks with no recorded events appear explicitly with zero-valued additive metrics.

### Main fields

```text
week_start

actor_id
actor_name

event_count

state_based_event_count
non_state_event_count
one_sided_event_count
combat_event_count

combatant_fatalities
actor_deaths_suffered

civilian_fatalities
one_sided_civilian_fatalities

best_fatalities
low_fatalities
high_fatalities

active_location_count

one_sided_event_share
```

### Definitions

```text
combat_event_count
    = state_based_event_count
    + non_state_event_count
```

```text
one_sided_event_share
    = one_sided_event_count / event_count
```

For observed weeks with zero events:

```text
one_sided_event_share = 0
```

### `actor_deaths_suffered`

For actor-specific rows, this is the weekly sum of deaths attributed to that actor side.

For:

```text
actor_id = "__ALL__"
```

the value should be missing (`NA`) because an all-actor aggregate is not interpreted as a meaningful actor-specific loss variable.

### Expected invariants

```text
event_count >= 0

state_based_event_count
+ non_state_event_count
+ one_sided_event_count
= event_count
```

```text
combat_event_count
= state_based_event_count
+ non_state_event_count
```

```text
0 <= one_sided_event_share <= 1
```

For every week:

```text
__ALL__.event_count
```

must match the number of unique events in `events_clean.parquet` assigned to that week.

## 6. `data/derived/h3_weekly_metrics.csv`

### Purpose

Primary dataset for **Web 2 — Spatio-temporal Conflict Map**.

Events are aggregated into H3 cells to produce a consistent geographic grid over time.

### Format

CSV.

### Producer

`04_build_h3_metrics.py`

### Consumers

- Web 2 — H3 conflict map
- `07_validate_outputs.py`

### Unit of observation

One row = one actor × one week × one H3 cell.

As with the weekly metrics file, conflict-wide observations use:

```text
actor_id = "__ALL__"
```

### Spatial eligibility

Only events where:

```text
spatial_eligible = True
```

are included.

Events without valid coordinates remain available in the non-spatial datasets.

### Main fields

```text
week_start

actor_id
actor_name

h3_id
h3_resolution
h3_center_lat
h3_center_lon

event_count

state_based_event_count
non_state_event_count
one_sided_event_count
combat_event_count

combatant_fatalities
civilian_fatalities
one_sided_civilian_fatalities

best_fatalities

one_sided_event_share
civilian_fatality_share
one_sided_civilian_fatality_share
```

### Share definitions

```text
one_sided_event_share
    = one_sided_event_count / event_count
```

```text
civilian_fatality_share
    = civilian_fatalities / best_fatalities
```

```text
one_sided_civilian_fatality_share
    = one_sided_civilian_fatalities / best_fatalities
```

A zero denominator produces the configured zero-denominator value, normally `0.0`.

### Expected invariants

```text
h3_id is valid

resolution(h3_id) = configured H3 resolution

event_count >= 0

0 <= all shares <= 1
```

For conflict-wide rows in each week:

```text
sum(event_count across H3 cells)
```

must equal the number of unique spatially eligible events for that week.

### Purpose

Primary dataset for **Web 3 — Actor Violence Fingerprints**.

It summarizes each armed actor through temporal, behavioral, fatality, and geographic metrics.

### Format

### Producer

`05_build_actor_profiles.py`

### Consumers

- Web 3 — parallel coordinates / actor profile view
- actor filtering controls
- `06_build_event_windows.py`
- `07_validate_outputs.py`

### Unit of observation

One row = one canonical armed actor.

### Main fields

```text
actor_id
actor_name

first_event_date
last_event_date
active_week_count

total_event_count
combat_event_count
one_sided_event_count

combatant_fatalities_in_involved_events
actor_deaths_suffered

civilian_fatalities_in_involved_events
one_sided_civilian_fatalities

one_sided_event_share

active_location_count
active_h3_cell_count

events_per_active_week
one_sided_events_per_active_week
civilian_fatalities_per_active_week

```

### Interpretation notes

`combatant_fatalities_in_involved_events` means:

> total combatant fatalities in direct-combat events in which the actor was involved.

It does **not** mean fatalities suffered by that actor.

Actor-specific losses are represented separately by:

```text
actor_deaths_suffered
```

### Geographic spread

Two complementary measures are retained:

```text
active_location_count
active_h3_cell_count
```

The first is based on named UCDP locations.

The second uses the same H3 resolution adopted for Web 2.

### Visualization eligibility

Actors are not removed from this dataset because of low activity.

Instead:

```text
eligible_for_web3
```

marks actors that satisfy the configured minimum event threshold for default display in Web 3.

### Expected invariants

```text
actor_id is unique

total_event_count > 0

combat_event_count
+ one_sided_event_count
= total_event_count

0 <= one_sided_event_share <= 1
```

All counts and fatality values must be non-negative.

## 8. `data/derived/event_windows.csv`

### Purpose

Primary dataset for **Web 4 — Event-centred Before / After Analysis**.

It aligns major one-sided-violence episodes around a common relative-time origin:

```text
T0 = selected one-sided-violence peak week
```

This allows comparison of what happens before and after major episodes even when they occur on different calendar dates.

### Format

CSV.

### Producer

`06_build_event_windows.py`

### Consumers

- Web 4 — event-centred matrix
- event-window summary visualization
- `07_validate_outputs.py`

### Unit of observation

One row = one episode × one relative week.

With the default configuration:

```text
T-8 ... T-1 | T0 | T+1 ... T+8
```

each complete episode contains 17 rows.

### Main fields

```text
episode_id

actor_id
actor_name

peak_rank
t0_date
peak_metric_value

relative_week
calendar_week
is_observed_week

combat_event_count
combatant_fatalities
actor_deaths_suffered

one_sided_event_count
one_sided_civilian_fatalities
civilian_fatalities

active_location_count
```

### Episode detection

Episodes are detected automatically from actor-specific weekly time series.

Default peak metric:

```text
one_sided_civilian_fatalities
```

Candidate peaks:

- must have a positive value;
- must be local maxima;
- are ranked by severity;
- must respect the configured minimum temporal separation;
- are limited to the configured top K per actor.

Episode selection must be deterministic and must not depend on manual choice.

### Relative time

```text
relative_week = 0
```

identifies `T0`.

```text
relative_week < 0
```

represents weeks before the peak.

```text
relative_week > 0
```

represents weeks after the peak.

### Boundary policy

Weeks inside the observation period with no events are represented as zero.

Weeks falling outside the configured analysis period are not zero-filled.

Instead:

```text
is_observed_week = False
```

and analytical metrics remain missing.

This distinguishes:

> observed inactivity

from:

> absence of observation.

### Expected invariants

Within each episode:

```text
relative_week is unique
```

Exactly one row must satisfy:

```text
relative_week == 0
```

and:

```text
calendar_week at T0 == t0_date
```

The T0 one-sided civilian fatality value must match the peak value used to define the episode.

# Missing values and zero values

The project distinguishes carefully between `0` and missing values.

A value of:

```text
0
```

means that the observation exists and the measured quantity is zero.

A missing value means that the quantity is unavailable, not applicable, or outside the observation window.

Examples:

- a week within the study period with no one-sided events → `0`;
- `actor_deaths_suffered` for the synthetic `__ALL__` actor → missing;
- a relative event-window week outside the analysis period → missing and `is_observed_week = False`;
- an event without valid coordinates → coordinates may be missing and `spatial_eligible = False`.

This distinction must be preserved by both preprocessing and visualization code.
